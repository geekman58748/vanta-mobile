# Pitch deck — the "Native Android layer" slide

> **Why this file exists.** Vanta's UI is a WebView, and a judge who sees that in the
> first ten seconds writes the project off as a PWA wrapper — regardless of how much
> Kotlin is behind it. This is the one slide that answers that judgement with evidence
> instead of denial, and it is written to be lifted straight into the deck.
>
> Claims discipline follows `docs/pmf-narrative.md` §6: nothing here is a direction or a
> roadmap item. Every line is code in the APK, and §4 says where.

---

## 1. The slide

**NATIVE ANDROID LAYER**
### The UI is HTML for velocity. Everything the OS has to say yes to is Kotlin.

**1,160 lines of hand-written Kotlin** — none of it generated by the web build, none of it
reachable from a browser.

| | What it does | Why a web app cannot |
|---|---|---|
| **Receipts leave the app** | Writes the PDF through **MediaStore** (scoped storage — no storage permission asked for), marks it `IS_PENDING` until the bytes are whole, then hands the same URI to the system **share sheet** | There is no web API that can take a file *out* of a WebView. No `DownloadListener` was ever wired, so a `data:` URL used to vanish silently |
| **The phone asks for the person** | Platform **BiometricPrompt** before a spend is signed — biometrics *or* device credential, gate on the transaction, not the app | Not a permission the web layer can request. Zero added dependencies, no user-facing toggle |
| **Nothing is filmed without permission** | **FLAG_SECURE** on the whole window in the release build — no screenshots, no screen recording, no Recents thumbnail | Belongs to the window, not the page |
| **Gestures and insets arbitrated natively** | Pull-to-refresh is a real `SwipeRefreshLayout`, silenced by a ref-counted lock the web layer raises while a sheet is open; edge-to-edge insets applied in Compose | A downward drag inside a sheet would otherwise reload the whole app |
| **The viewport is measured, not trusted** | The shell probes the WebView's own `100vh` / `100dvh` and injects a fallback only when the measurement is a lie | The WebView's viewport units are the thing that is wrong |
| **The key never leaves the wallet** | Full **Mobile Wallet Adapter** client — `solana-wallet:` handoff, local websocket transport, v1 wire format, signed on the device | MWA is the Android-native signing path. There is no desktop equivalent, which is the point |

**Everything above is in the APK you can install.**
`android/app/src/main/java/com/vanta/privacywallet/`

## 2. Speaker notes (45 seconds, spoken over the slide)

> "We're going to say the thing you're all thinking. The UI is a WebView. It's the right
> call for a hackathon and we're not going to pretend otherwise.
>
> But look at what isn't in the WebView. When you save a receipt, it's Kotlin writing
> through MediaStore into your Downloads, then handing the URI to the system share sheet —
> because there is no web API that gets a file out of a WebView, and the version of this
> that pretended otherwise was silently saving nothing.
>
> When you confirm a send, the phone asks for *you* — the platform biometric prompt, no
> added dependency, no setting to turn it off. When you open the release build, the window
> refuses to be screenshotted or recorded.
>
> And when you sign, the key comes from your wallet through Mobile Wallet Adapter. Vanta
> never holds it. That path only exists on Android — it's the reason this is a phone app
> and not a website.
>
> 1,160 lines of Kotlin. The web layer is the skin; the OS boundaries are all native."

**If asked "why not just make it a native UI?"** — Answer: the WebView is what made 83
commits in fourteen days possible, and every OS capability we actually need is native
already. Rewriting the UI in Compose would not make the wallet more private by one byte.

**If asked "is the WebView a security problem?"** — Answer: it loads from
`https://appassets.androidplatform.net`, served out of the APK by `WebViewAssetLoader` —
not from the network, and not from `file://`. Off-origin navigation leaves the app for the
system browser. JS-to-native is one interface, `window.VantaShell`, with five methods.

## 3. What NOT to say (inherited from `pmf-narrative.md` §6)

- 🚫 **Not** "secure enclave", "hardware-backed", "TEE". The shielded key is still in
  `localStorage` today; Seed Vault custody is the roadmap fix, and `BETA-TEST.md` says so.
- 🚫 **Not** "anonymous" or "untraceable". The receipts themselves refuse this language.
- 🚫 **Not** "no server". The relayer and faucet are live services; the *key* is what
  stays on the device.
- ⚠️ FLAG_SECURE is **release-only** until the demo video is shot. Do not show the debug
  build's title bar and call it a privacy feature; show the release APK.
