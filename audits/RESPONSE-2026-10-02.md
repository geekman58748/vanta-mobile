## Accepted

### A1 — `bigint-buffer` 1.1.5, GHSA-3gc7-fjrx-p6mg · High · **disclosed, cannot be fixed**

This is the review's one finding with no remedy, and it is right. `bigint-buffer@1.1.5` reaches us
through `@solana/web3.js` — transitively, not a declared dependency of ours
(`pnpm-lock.yaml:1655`) — and it is in the shipped APK: `toBigIntLE` is present in
`android/app/src/main/assets/www/assets/esm-BRwf25uH.js`.

No fixed version has been published, so there is no upgrade to take. We are not going to pretend
otherwise. It is recorded in `README.md` → *Known limitations*, it is the item we watch for a patch
on, and the exposure sits behind the fact that this is a devnet build holding no value. On mainnet
this would be a release blocker, not a note.

### A2 — `uuid` 8.3.2, GHSA-w5hq-g745-h8pq · Medium · **accepted, reachability argued**

**This review corrected us, and the correction stands.** Our earlier position was that
`uuid` and `stream-json` are server-only because they arrive via `jayson` in
`relayer/package-lock.json`. That is wrong for `uuid`: jayson also reaches the *client* graph
through `@solana/web3.js` → `rpc-websockets` → `jayson` → `uuid@8.3.2` (`pnpm-lock.yaml:5185`), and
the library is in the shipped bundle at
`android/app/src/main/assets/www/assets/index.browser.esm-CqbKqh0d.js`. We checked before claiming
otherwise. The finding is valid and is accepted as Medium.

The one qualification is reachability, stated as exactly what the bundle shows: that chunk contains
`uuid.v1()` (its `lastTimestamp` bookkeeping) and the `crypto.getRandomValues()` path, and contains
**no v3, v5 or v6 code** — `grep -c` for `md5`, `sha1`, `v3(`, `v5(` and `v6(` all return 0. The
advisory is *"Missing buffer bounds check in v3/v5/v6 when `buf` is provided"*, so the vulnerable
entry points are absent from what we ship. We record it as accepted rather than dismissed, because
"not reachable in this bundle" is a claim that expires the moment a dependency changes its import.

### A3 — `allowBackup="true"` · Medium · **disclosed before this review**

Already in `README.md` → *Known limitations*, verbatim: *"The manifest also sets
`android:allowBackup="true"`, so `adb backup` can copy the WebView data directory off a device with
USB debugging enabled and recover that key from it,"* with the fix named in the same paragraph. It
sits on top of finding **C3** of our own audit — the fallback wallet's spend key is plaintext in
WebView `localStorage` (`vanta-wallet` / `vanta-wallet-session`, read at `src/lib/backup.js:86`).
Both are disclosed, and both close when the fallback wallet goes away. We are shipping this APK as
it stands.

### A4 — the Helius key is inlined into the bundle · High (×10) · **disclosed in the README**

`src/App.jsx:48` and `src/lib/config.js:18` are the real case, and `README.md` → *Known limitations*
already covers it: `VITE_HELIUS_API_KEY` is compiled into the bundle so a judge can run the release
APK against devnet without signing up; it is a devnet key, the endpoint is devnet only, and the
relayer uses its own RPC so server traffic cannot burn it. The remaining eight rows are
`scripts/*.mjs` — Node scripts with no bundler.

### A5 — `stream-json` 1.9.1, GHSA-528h-pc64-c93x · Medium · **accepted, server-side only**

`stream-json` reaches `relayer/package-lock.json` through `jayson` and is **not** in the www bundle
(no match for it in `android/app/src/main/assets/www/assets/`). It is a genuine Medium on a service
that parses untrusted input, and we will take it when jayson ships a release that moves off 1.9.1.

### A6 — hygiene · Low · **accepted, will fix**

- **Docker base images** (`faucet/Dockerfile:12`, `relayer/Dockerfile:7`) — pin to a digest.
  `node:22-alpine` currently resolves to
  `sha256:0a7108bf6c7bf5de370ffb1a3ed6be93d405b43ff159f681a8d18c0e2bc2e402`.
- **`@solana/web3.js` v1** (12 rows) — correct, Low, and true: new work should use `@solana/kit`.
  The app lazy-imports v1 in nine places; migrating the client is a roadmap item, not a patch.

## Disputed

### D1 — "non-local `http://` endpoint is hardcoded" × 5 · Medium

`AppPreview.jsx:70`, `App.jsx:74`, `Onboarding.jsx:46`, `:319`, `:382` — every one of the five is
`xmlns="http://www.w3.org/2000/svg"`. That is the SVG namespace identifier, required by the SVG
spec. It is not a URL, nothing is fetched from it, and changing it would break the markup.
**Five of the eleven Mediums in our code are this.**

### D2 — "an exported component has no permission on it" · Medium · `AndroidManifest.xml:42`

`MainActivity` is the `MAIN`/`LAUNCHER` activity. `exported="true"` is **mandatory** for a launcher
activity — without it the app has no icon. The manifest has exactly one `<intent-filter>` and no
deep-link or custom-scheme entries, so there is nothing for another app to drive. The report's own
caveat — *"If it handles wallet actions or deep links"* — does not apply.

### D3 — "data is written to external storage" × 2 · Medium · `FileSaver.kt:198,212`

This is the receipt PDF, and it is the point of the feature: a receipt the user cannot find is not
a receipt. API 29+ goes through `MediaStore`. The legacy path cannot write to public Downloads
because the app requests no `WRITE_EXTERNAL_STORAGE`, and the code says so and falls back to
app-private storage, reporting the real location instead of promising "Downloads". No key material
is written by this path.

### D4 — "key material is being passed to a logger" × 3 · Medium

Not one of the three passes key material:

- `src/App.jsx:596` — `console.log('[vanta] identity owner:', signer.address, …)`. `signer.address`
  is a **public** key, which is exactly what the finding says to log instead.
- `relayer/server.js:149` — `console.warn('⚠  No RELAYER_KEYPAIR and no relayer-keypair.json — generating a dev-only key.')`.
  A literal string; no variable at all.
- `faucet/server.js:270` — `console.error('✗ Refusing to run in production without a token …')`.
  A literal string; no variable at all.

### D5 — the two Dockerfile rows are counted twice

`faucet/Dockerfile:12` and `relayer/Dockerfile:7` appear as code Mediums (#5, #7) **and** again as
package Lows (#17, #18). Same two lines, four rows. We accept the underlying point once — see A6.

## Notes

The report's own note — *"Nothing here needs fixing"* — sits directly above a five-item Fix-first
list, and its summary counts 23 code findings under *"Nothing was confirmed as a defect."* We have
taken the items that are real and said so; the rest is above, with the code to check.

One note is **accepted and worth fixing**: `WebShellChromeClient.kt:42` (`onCreateWindow`) starts
`ACTION_VIEW` on any URL from `window.open` without scheme validation. The app never calls
`window.open`, so it is unreachable today, but a scheme check costs one line and we will add it.

## What the report did not reach

Recorded so a reader knows the shape of the gap, not to score points: the review found **zero**
mention of the plaintext `secretKey` in WebView `localStorage` (our own audit's finding **C3**), it
does not cover the MWA signing path at all, and it does not reach the relayer's
parse-fail-then-allow program-ID check (`relayer/server.js:54`, where our own comment flags it). An
automated pattern scan cannot see any of those — which is why we keep the adversarial self-audit in
[`AUDIT-2026-09-27.md`](AUDIT-2026-09-27.md) and do not treat this response as a substitute for it.
